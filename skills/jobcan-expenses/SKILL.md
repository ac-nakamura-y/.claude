# Jobcan Expense Claim

対象月に出社した日を確定し、ジョブカンの小口経費精算に往復の通勤費として入力して下書き保存する。申請ボタンは押さず、提出はユーザーに委ねる。勤怠の打刻修正、有給申請、シフト申請そのものは扱わない。

## Prerequisites

ジョブカンはログイン済みの Chrome で開く。ログイン画面が出た場合は認証情報を入力せず、ユーザーにログインを依頼して待つ。

| Tool | Purpose |
| :-- | :-- |
| Claude in Chrome | 申請書の操作（ `navigate` , `find` , `read_page` , `form_input` , `computer` ） |
| Google Calendar | 勤務場所から出社日を取得（ `list_events` ） |

## Defaults

ユーザーの指定がない項目は次の値を使う。対象月は実行日を基準に決め、日付はハードコードせず `date +%Y-%m-%d` で確認する。

| Item | Value |
| :-- | :-- |
| ジョブカン | `https://id.jobcan.jp/users/sign_in` |
| 申請書 | 小口経費精算 |
| 出発駅 | 海老名（鉄道） |
| 到着駅 | みなとみらい（鉄道） |
| 往復区分 | 往復 |
| 申請者 | 中村（ユーザー番号 `0042` ） |
| 所属部門 | marutto |
| 対象月 | 実行日の月 |

## Workflow

出社日の確定から下書き保存まで、次の順に進める。

```mermaid
flowchart LR
  officeDays[出社日確定] --> formHeader[申請情報]
  formHeader --> commuteRows[通勤費明細]
  commuteRows --> applicant[申請者情報]
  applicant --> draftSave[下書き保存]
```

### Office Days

Google カレンダーの勤務場所とジョブカンのシフトの両方から対象月の出社日を取得し、二つの日付リストが一致することを確認する。食い違いがあれば、その日付を挙げて作業を止め、ユーザーに確認する。どちらか一方を推測で採用しない。

ジョブカンのシフトは、勤怠タブの左メニューからシフト、シフト申請と進み、上部で対象月を選んで表示を押すと確認できる。

### Form Header

経費/WF タブから申請機能、申請すると進み、小口経費精算の申請書を開く。表示された雛形の先頭に次の三つを入力する。旅費交通費明細と経費明細には入力しない。

| Field | Value |
| :-- | :-- |
| 申請タイトル | 対象月をゼロ埋めした2桁（9月なら `09` ） |
| 申請月 | 雛形の `MM` の位置に同じ2桁 |
| 申請期間 | 雛形の `〇` の位置に、前月から対象月までをゼロ埋めせず記入（対象月が9月なら `8` から `9` ） |

### Commute Details

確定した出社日について、1日につき1明細を作る。2日目以降は明細行の右にある追加ボタンを押し、日付を変えて同じ手順を繰り返す。

| Step | Action |
| :-- | :-- |
| 1 | 明細の出発を選択し、利用日にその出社日を入力する |
| 2 | 出発駅に `海老名` と入力して検索し、候補から鉄道の海老名駅を選ぶ |
| 3 | 到着駅に `みなとみらい` と入力して検索し、鉄道のみなとみらい駅を選ぶ |
| 4 | 経路を検索を押し、一番上に表示された経路のこの経路を選択を押す |
| 5 | 目的と備考は空のまま、設定を押す |
| 6 | 追加された明細行の往復の項目を、片道から往復に変更する |

### Applicant Info

申請日には作業日を入れる。名前はユーザーを検索から `中村` で検索し、 `0042` のユーザーを選んで決定する。所属部門も同じ手順で marutto を選ぶ。オフィス出社日数には、作成した通勤費の明細行数と同じ数を入れる。

### Draft Save

保存前に、対象月、出社日の一覧、明細行数、オフィス出社日数をユーザーに提示して確認を得る。確認が取れたら、申請書の一番下の下書き保存を押して終了する。申請ボタンは押さない。

## Constraints

出社日数、通勤費の明細行数、オフィス出社日数の三つは必ず一致させる。手順どおりのボタンや項目が画面上に見つからない場合は、別の要素で代用せず、その時点で止めて状況をユーザーに報告する。
