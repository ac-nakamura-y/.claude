# BPMN Guideline

業務フローを BPMN 2.0 XML で記述するときの規約を定める。各ルールには出典として BPMN 仕様の条番号、 Bruce Silver の BPMN Method and Style（M&S）、 BPM-J の機能階層（FL）、独自のいずれかを示す。

## Notation Level

使用する要素は Analytic 適合サブクラスの範囲に限る（BPMN §2.2.2）。 BPMN 仕様は Descriptive、 Analytic、 Common Executable の3つの適合サブクラスを定めており、 Analytic は業務担当者との合意に加えて、例外を含めた業務の分析までを扱える。

## Granularity

1つの BPMN プロセスで業務（FL4）を1つ表し、その中のアクティビティは要素作業（FL6）を目安とする（FL）。判断に使う階層の目安を以下に示す。

| 階層 | 名称 | 目安 |
| :-- | :-- | :-- |
| FL4 | 詳細業務機能 | 業務機能のマイルストーン、中間成果物の確定、組織間の受け渡し |
| FL5 | 単位作業 | 担当者の役割単位の受け渡し。タスクリストに表示される1件 |
| FL6 | 要素作業 | 「何を使って何をする」でまとまる、連続した操作の塊 |
| FL7 | 単位操作 | ファイルを開く、選ぶ、コピーして貼り付けるなどの操作 |

画面遷移や入力チェックなどのシステム上の条件分岐と、クリックなどの操作レベルの動作は描かない（独自）。

## Rules

記述ルールを要素ごとに示す。

| 対象 | ルール | 出典 |
| :-- | :-- | :-- |
| 開始イベント | 流入するシーケンスフローを持たない | BPMN §10.5.2 |
| アクティビティ | 名前は目的語と動詞で書く（例：購入申請を登録） | M&S |
| メッセージイベント | 送る側は送信（スロー）イベント、受け取る側は受信（キャッチ）イベントで描く | BPMN §10.5.4 |
| メッセージイベント | ラベルは「〜送信」「〜受信」とし、要素の型と一致させる | 独自 |
| ゲートウェイ | ラベルは問いの形にする（例：承認する？） | M&S |
| ゲートウェイ | 問いのラベルを使う場合、流出するシーケンスフローは YES と NO の2つにそろえる | M&S |
| ゲートウェイ | YES と NO の行き先を、答えの業務上の意味と整合させる | 独自 |
| レーン | 同じ担当者を指すレーンは、すべてのフローで同じ名前にする | 独自 |
| レーン | 要素を1つも持たないレーンを置かない | 独自 |

## Layout

bpmn.io にはページ設定がないため、複数のフローで見た目と出力サイズがそろうよう、レイアウトを数値で定める（独自）。

- プールは起点 (0, 0)、横幅 `1820` で描く
- レーン1本の高さは `120` とする
- 要素間の水平間隔は `60` とする
- 主フローは左から右へ流し、分岐と合流は上下に展開する
