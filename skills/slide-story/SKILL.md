# Slide Story

スライドは、読み手が判断するための物語である。情報を綺麗に並べただけの資料は、何を伝えたいのかが伝わらず、読み手に「AI がそのまま出した」と感じさせる。このスキルは、資料の作成とレビューの両方で、全体の物語、スライド間の強弱、スライド内の情報構造を、役員と現場という二つの視座から整える。描画や装飾は扱わず、HTML や pptx、テンプレート固有のスキルと組み合わせて使う。

## Principles

判断の土台となる原則を示す。以降の構造・手順・チェックはすべてこの原則から導かれる。

| 原則 | 内容 |
| :-- | :-- |
| 読み手と判断から始める | 誰が、どの場で、何を判断するために読むのかを先に決める。現場への報告と部長への報告は別の資料である |
| 主張で語る | タイトルは「やったこと」ではなく、読み手が持ち帰る結論である。目次（タイトルの並び）だけで物語が成立する |
| 定義してから使う | 用語・指標・分類・比較対象は、結果より前に置く。初出の用語に定義のないスライドは読めない |
| 強弱をつける | 伝えたいキースライドと、補足・参考を見て分かるように分ける。部長報告は読み進める資料ではなく、少ない枚数と情報量で印象を渡す資料である |
| 一貫させる | 用語・色の意味・フローの向き・比較対象の位置・数値を資料全体で揃える。1 枚だけ違うと「このページは別の人が作ったのか」と読み手の理解が途切れる |
| 自分の意思を入れる | AI の出力や集めた素材をそのまま並べない。すべてのスライドを自分の言葉で説明でき、固有名詞と数値の裏取りが済んだ状態で出す |

## Readers

一つの資料で、役員と現場の二つの視座を同時に満たす。両者は読み方が違うため、キースライドが役員に答え、補足スライドが現場に解像度を与える構造で両立させる。

| 視座 | 読み方 | 求める答え |
| :-- | :-- | :-- |
| 役員（部長・経営層） | ぱらぱらとめくり、印象で判断する | WHY と目的、目標とギャップ、打ち手と解決の見込み・時期、置き換える価値と将来像、自分が判断すべきこと |
| 現場（相手と自組織の担当者） | 自分の業務に当てはめて読む | 具体的な工程、誰が何をいつやるか、自分の負荷がどう変わるか、指摘や成果物の実例、修正前後の比較 |
| 両者共通 | 前のスライドの結論だけで次を読む | 用語の定義、比較対象、意味の揃った色と図形、矛盾のない数値 |

役員向けのテストは、タイトルとキースライドだけを 60 秒で読んで物語が成立するかである。現場向けのテストは、読んだ担当者が翌日から同じ手順を回す姿を想像できるかである。「私たちが頑張った」ではなく「あなたの業務がこうなる」で書く。

## Storyline

資料全体の物語は、目的から将来像へ向かう問いの連鎖で組む。定義より前に結果を出さず、内訳より前にサマリーを出す。以下は検証や PoC の報告を標準とした段階で、提案や企画の資料では評価と結果の段階を「現状と課題」「提案」「効果の見込み」に置き換える。問いの連鎖と順序の原則は変えない。

```mermaid
flowchart LR
  why[目的と前提] --> process[現状の工程]
  process --> measure[評価の定義]
  measure --> summary[結果サマリー]
  summary --> detail[内訳]
  detail --> gap[残課題]
  gap --> action[打ち手と見込み]
  action --> vision[将来像]
```

| 段階 | 答える問い | 置くもの |
| :-- | :-- | :-- |
| 目的と前提 | なぜやるのか、何を置き換えるのか | 目的、目標、対象範囲、体制 |
| 現状の工程 | どういうやり方をしているか | 工程の全体像 1 枚、各工程の担当と道具 |
| 評価の定義 | 何をどう測るか | 指標、分類、集計方法、比較対象 |
| 結果サマリー | 目標に対してどこまで来たか | 達成・未達、ギャップ、比較対象との差 |
| 内訳 | 何が多く、何が減り、何が残ったか | 分類ごとの件数と推移、具体例 |
| 残課題 | なぜ残っているか | 課題と原因 |
| 打ち手と見込み | 何を、いつまでに、どう解くか | 打ち手ごとに動かす指標と時期 |
| 将来像 | 続けるとどうなるか | 置き換えの姿、拡大の道筋、次の判断時期 |

物語を組むときに守る観点を示す。

| 観点 | 規則 |
| :-- | :-- |
| 接続 | 前のスライドの結論が次のスライドの問いになる。接続が弱い箇所は、間に 1 枚入れるか順序を入れ替える |
| 章と中身の一致 | 章タイトルが「業務適合性」なら、その章のスライドは業務適合性の話で統一する。別の話題が混ざれば章を分ける |
| 記憶負荷 | 数枚前の内容を覚えていないと読めない構成を避ける。サマリー 1 枚を先に置き、詳細はその後か参考に回す |
| 強弱 | キースライドを前半に集め、細かな定義や分析の経緯は「参考」と明記した付録へ移す。読み手がどこを見ればよいか迷わない |
| 議論ポイント | 読み手に判断や意見を求める箇所を決め、その根拠となるスライドをキースライドにする。最後に何を判断してほしいかを明記する |
| 打ち手の重み | 課題を並べるスライドで読み手が見たいのは、課題の多さではなく打ち手と解決の見込みである。課題と打ち手の分量を逆転させない |

## Slide

1 枚のスライドは、1 つの主張とそれを支える根拠で構成する。読み手はタイトルを読み、視線の流れに沿って根拠を確かめ、主張を持ち帰る。

### Title and Lead

タイトルとリード文は、そのスライドで読み手に持ち帰らせる主張を書く。「〜を比較しました」「〜を整理しました」のような作業の報告は主張ではない。「数を比較したところ」のような前置きは許容するが、結論を必ず続ける。リード文で述べた主張（例：相手の工程に合わせた）は、本文のどこがそれに当たるかを示す。タイトルが中身と一致しているかは、スライドの第一の検査項目であり、2 段構成のスライドならタイトルも 2 段の内容を表す名前にする。

### Layout

配置は読む順序を決める。縦に並べた要素は縦に読まれるため、途中で横に読ませると視線の流れが崩れ、読み手は何をどう読めばよいか分からなくなる。要素の並び順、フローの向き（左から右など）、比較対象の位置（例：比較対象を常に右）を資料全体で固定する。1 枚の中にも強弱をつけ、主張を支える要素を最も大きく置き、補足は小さく添える。すべてを同じ大きさで並べると、どこを見ればよいか伝わらない。

### Visual Meaning

色・枠・矢印・太字は、すべて意味を持つ。注目させる色と並列を示す色を混ぜると、どこを見ればよいか伝わらない。赤い枠がコメントなのか工程なのか分からない図は、読み手の判断を止める。意味のない色分けは消し、意味のある色分けは凡例かリード文で説明する。表やグラフは図形の組み合わせではなく、実データのグラフとして置く。

### Numbers and Labels

数値とラベルは、読み手が検証できる形で置く。

| 対象 | 規則 |
| :-- | :-- |
| 単位 | 件数で書く。割合や 100% 積み上げは、絶対量の変化を隠す |
| 比較対象 | 以前の試行、従来のやり方、目標値を必ず置く。比較対象がなければ、良くなったかどうか判断できない |
| 整合 | 同じ数値は資料全体で一致させる。あるページで 5 件、別のページで 4 件なら、どちらかが誤りである |
| 推定値 | 実測から「まだ数回かかる見込み」と言えばよく、根拠のない推定件数を出さない。出すなら根拠と自分の判断を添える |
| 分類の名前 | 重なりなく、役員が一目で「こういう間違いのことだ」と分かる名前にする |
| 分類の軸 | 分類の軸（例：工程別）に別の軸（例：ルール化の有無）を混ぜない。途中で現れた新しい区分は、なぜ現れたか（工程の変更など）を説明してから数に入れる |
| 具体例 | 分類ごとに、最初はどういう状態で、どこまで直り、何が残っているかを修正前後の実例で示す |

### Wording

評価語は、読み手の視座で意味が変わる。「一部改善」は、役員には既存の仕組みに手を入れて良くなったと読まれるため、達成か未達か、改善余地があるかを明示する。「減少」と書くなら、他のスライドの数値がそれを裏付けていなければならず、質が変わったのなら「質が変わった」と書く。確認していない項目を「問題なし」「OK」と書かない。「社内」「先方」のような相対的な主語は、どの組織かを書く。件数を減らす打ち手と時間を減らす打ち手のように、効く指標が違う打ち手は分けて書く。

## Create

作成は、読み手の決定から自己レビューまでを順に進める。描画は最後であり、物語と構造が固まるまで装飾に時間を使わない。

```mermaid
flowchart LR
  reader[読み手] --> message[一文]
  message --> outline[目次]
  outline --> slides[各スライド]
  slides --> consistency[一貫性]
  consistency --> selfReview[自己レビュー]
```

1. 読み手：誰が、どの場で、何を判断するために読むかを一文で決める。役員が読むなら枚数を絞り、現場が読むなら工程の実例を増やす。
2. 一文：資料全体で伝えたいことを一文で書く。読み手が読み終えたあとに何を思い、何を決めるかまで含める。
3. 目次：Storyline の段階に沿って、スライドのタイトル（主張）を並べる。タイトルだけを読んで物語が成立するまで並べ替え、キースライドに印をつけ、参考に回すものを分ける。
4. 各スライド：主張、根拠、配置、持ち帰らせることを決めてから中身を作る。Readers の二つの視座で、そのスライドが誰の何に答えるかを確かめる。
5. 一貫性：用語の初出と定義、色の意味、フローの向き、比較対象の位置、数値の一致を資料全体で揃える。
6. 自己レビュー：Review の手順で自分の資料を見る。説明できないスライド、裏取りのない固有名詞と数値は、出す前に直すか削る。

## Review

レビューは、役員・現場・一貫性の 3 回の通読で行う。分類や名称、物語の順序といった根本的な問題は後続のすべてに波及するため、最初に見つけて最初に報告する。

| 通読 | 視座 | 見ること |
| :-- | :-- | :-- |
| 1 回目 | 役員 | タイトルとキースライドだけを 60 秒で読む。何を伝えたい資料か、目標とギャップ、打ち手と見込み、判断すべきことが分かるか |
| 2 回目 | 現場 | 各スライドを読む。工程を自分で回せるか、用語が定義されているか、実例があるか、負荷がどう変わるか |
| 3 回目 | 一貫性 | 用語、色の意味、フローの向き、比較対象の位置、数値、章タイトルと中身の一致を資料全体で突き合わせる |

各スライドには次の問いを当てる。答えがスライド上にない問いが、そのまま指摘になる。

| 問い | 見る場所 |
| :-- | :-- |
| このページで見せたいのは何か。タイトルがその答えになっているか | タイトル、リード文 |
| 口頭・注記・補足メモで補った説明は、スライドに書いてあるか | 本文 |
| この用語・指標・分類は、このスライドより前に定義されているか | 前のスライド |
| 目標はどこに書いてあり、今どこまで来ていて、差分は何か | 結果サマリー |
| 比較対象はあるか。それは常に同じ位置にあるか | 表、グラフ |
| この色・枠・矢印は何を意味するか。強調と並列が混ざっていないか | 図、凡例 |
| 評価語（改善・減少・OK）は、他のスライドの数値と矛盾しないか。確認していないものを「問題なし」としていないか | 本文、他のスライドの数値 |
| 打ち手ごとに、どの指標をいつまでに動かすかが書いてあるか | 打ち手のスライド |
| 前のスライドの結論だけで、このスライドが読めるか | 前後の接続 |
| 固有名詞・取引先名・数値の裏取りは済んでいるか | 全体 |

### Report

報告は、想定した読み手と判断、60 秒テストの結果、資料全体の一文から始める。一文が資料にないときは案を書き、資料にない事実は［ ］で空欄にして推測で埋めない。指摘は、物語・構造、スライド単位、表現の順に並べ、各指摘にスライド番号、読み手がどう受け取るか（例：部長が見たとき既存の仕組みの改善に見える）、具体的な直し方を添える。出す前に必ず直すもの（裏取りのない固有名詞、目標の欠落など）には「必須」と付す。構成案や文字だけの下書きでは、配置・色・グラフの検査を「要確認」として描画後に回す。良い点の列挙は不要で、各節の末尾に直せば資料がどう変わるかを 1 行で書き、報告の末尾に Checklist の判定を付す。

```markdown
## 前提
- 読み手と判断: クライアントの部長が、本番化の可否を判断する。
- 60 秒テスト: タイトルだけでは目標とギャップが読めない。
- 一文: 9 本の検証で指摘は［N］件/本まで減り、残る［分類名］は［時期］までに解く。

## 物語・構造
- 必須 p.23-30: 結果が定義より前に出ている。p.26 の分類を p.23 の前に移し、結果サマリー 1 枚を先頭に置く。

## スライド
- p.25: タイトル「評価の前提」と中身（指摘の分類）が一致しない。「指摘の 7 分類と集計方法」に改める。

## 表現
- p.30: フローが上から下で、他のスライドの左から右と違う。向きを揃える。
```

## Checklist

作成では出す前の関門として、レビューでは報告の末尾の判定として、次の項目をすべて確認する。

| 領域 | 項目 |
| :-- | :-- |
| 物語 | 一文メッセージがあり、目次だけで物語が成立する |
| 物語 | 定義が結果より前、サマリーが内訳より前にある |
| 物語 | キースライドと参考が見て分かり、参考には「参考」と書いてある |
| 役員 | 目標、現在地、ギャップが 1 枚で分かる |
| 役員 | 打ち手ごとに解決の見込みと時期があり、将来像と判断してほしいことがある |
| 現場 | 工程が担当・順序・道具まで具体で、実例がある |
| 現場 | 相手側の負荷と約束事（レビューのタイミングなど）が書いてある |
| スライド | タイトルが主張で、中身と一致する |
| スライド | 1 つの軸、1 つの視線の流れで読める |
| 一貫性 | 用語・色の意味・フローの向き・比較対象の位置が全体で揃う |
| 一貫性 | 数値が全体で一致し、件数で書かれ、比較対象がある |
| 姿勢 | すべてのスライドを自分の言葉で説明でき、固有名詞と数値の裏取りが済んでいる |
